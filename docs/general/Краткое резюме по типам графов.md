# Краткое резюме по типам графов

## 📊 Три типа графов в AQ Graph Engine

---

## 1️⃣ WorkflowGraph — Основной сценарий агента

### 🎯 Суть
**Главный pipeline агента** — полный сценарий работы от начала до конца.

### 💡 Для чего
- Автоматизация процесса разработки (анализ → генерация → тестирование)
- Интерактивные мастера с UI формами
- Code Review процессы
- Создание документации

### ⚙️ Ключевые возможности
- ✅ **Параллельное выполнение** — один узел запускает несколько веток
- ✅ **Приостановка для UI** — ждёт ввода пользователя, продолжает
- ✅ **Интерактивные узлы** — userInput, manualReview, fileUpload, coCreationChat
- ✅ **Композиция** — вызывает InstructionGraph как подграф
- ✅ **Обработка ошибок** — рёбра onError для альтернативных путей

### 🔧 Основные узлы
- `llmAction` — запрос к LLM
- `fileRead` / `fileWrite` — работа с файлами
- `userInput` — запрос данных у пользователя (с Dynamic UI)
- `manualReview` — ожидание подтверждения
- `runInstruction` — вызов Instruction графа
- `gitCommit` — коммит в Git

### ⚠️ Ограничения
- ❌ Нет циклов (должен быть DAG)
- ❌ Условия не реализованы полностью
- ❌ Нет timeout и retry

### 📝 Пример
```
[fileRead] → [llmAction] → [userInput] → [fileWrite] → [gitCommit]
```

## 2️⃣ InstructionGraph — Переиспользуемая инструкция

### 🎯 Суть
**Атомарная бизнес-логика с контрактом** — как функция, но в виде графа.

### 💡 Для чего
- Переиспользуемая логика (анализ кода, генерация тестов)
- Композиция Skills в бизнес-процесс
- Версионирование бизнес-логики
- Сложные ветвления и проверки

### ⚙️ Ключевые возможности
- ✅ **Контракт входов/выходов** — чёткий интерфейс
- ✅ **Валидация через JSON Schema** — проверка перед выполнением
- ✅ **Циклы разрешены** — с защитой (maxSteps = 20)
- ✅ **Ветвления** — через validationCheck
- ✅ **Вызов из Workflow** — через узел runInstruction

### 🔧 Основные узлы
- `systemAction` — вызов Skill (LLM, файлы, векторный поиск)
- `validationCheck` — проверка условия (ветвление)
- `stepDescription` — описательный шаг
- `userInputRequest` — запрос ввода (упрощённый)

### 📋 Контракт
```json
{
  "inputs": [
    {"name": "source_code", "type": "string", "required": true}
  ],
  "outputs": [
    {"name": "analysis", "type": "string"}
  ]
}
```

### ⚠️ Ограничения
- ❌ Максимум 20 шагов (защита от бесконечных циклов)
- ❌ Нет UI узлов (нельзя запросить ввод у пользователя)
- ❌ Нет параллельного выполнения

### 📝 Пример
```
Instruction "Code Analyzer":
  Вход: source_code
  [systemAction: llm_ask] → [validationCheck: результат не пустой?]
    ├─ true → [Возврат analysis]
    └─ false → [Ошибка]
```

## 3️⃣ PromptGraph — Шаблон промпта для LLM

### 🎯 Суть
**Конструктор промптов с переменными** — промпты тоже графы!

### 💡 Для чего
- Переиспользование промптов в разных Workflow
- Версионирование промптов (откат к предыдущей версии)
- Подстановка переменных из контекста
- Визуальное редактирование промптов

### ⚙️ Ключевые возможности
- ✅ **Переменные** — `{{source_code}}` заменяется значением
- ✅ **Версионирование** — каждое изменение = новая версия
- ✅ **Композиция** — промпт из нескольких блоков
- ✅ **Экспорт/импорт** — через JSON

### 🔧 Основные узлы
- `textBlock` — блок текста с переменными `{{var}}`
- `variable` — объявление переменной (документация)
- `fileContext` — контекст из файла (планируется)

### 📝 Пример
```json
{
  "type": "textBlock",
  "data": {
    "content": "Ты опытный разработчик.\n\nПроанализируй код:\n\n{{source_code}}\n\nНайди проблемы."
  }
}
```

**Компиляция:**
```
Контекст: {source_code: "function main() {}"}
Результат: "Ты опытный разработчик.

Проанализируй код:

function main() {}

Найди проблемы."
```

### ⚠️ Ограничения
- ❌ Нет условной логики (if/else)
- ❌ Нет циклов
- ❌ Нет вложенных промптов

## 🔄 Как они работают вместе

### Архитектура композиции

```
WorkflowGraph (главный агент)
  ├─ Узел: llmAction
  │    └─ Использует: PromptGraph "Analyze Code"
  │
  ├─ Узел: runInstruction
  │    └─ Вызывает: InstructionGraph "Code Analyzer"
  │         ├─ Узел: systemAction (tool_id: llm_ask)
  │         │    └─ Использует: PromptGraph "Detailed Analysis"
  │         └─ Узел: validationCheck
  │
  └─ Узел: userInput (с Dynamic UI)
```

### Пример реального сценария

**Задача:** Проанализировать код, запросить подтверждение, создать отчёт.

**Workflow:**
```
1. [fileRead] — читаем main.dart
2. [runInstruction: "Code Analyzer"] — анализируем
   └─ Instruction внутри:
      - [systemAction: llm_ask с PromptGraph "Analysis"]
      - [validationCheck: результат не пустой?]
3. [userInput] — показываем результат, запрашиваем подтверждение
4. [fileWrite] — сохраняем отчёт
5. [gitCommit] — коммитим
```

## 💪 Преимущества подхода "Граф как Закон"

### 1. Унификация
Всё (workflow, инструкции, промпты) — это графы. Один механизм для всего.

### 2. Версионирование
Каждый граф автоматически версионируется. Можно откатиться к любой версии.

### 3. Визуализация
Логика видна визуально. Не нужно читать код.

### 4. Переносимость
Экспорт/импорт через JSON. Можно делиться графами между проектами.

### 5. Композиция
Графы вызывают другие графы. Модульная архитектура.

### 6. Приостановка
Workflow может остановиться, дождаться ввода, продолжить.

## 🎯 Когда что использовать

### Используй WorkflowGraph для:
- ✅ Полного сценария работы агента
- ✅ Интерактивных процессов с пользователем
- ✅ Оркестрации нескольких инструкций
- ✅ Процессов с параллельным выполнением

### Используй InstructionGraph для:
- ✅ Переиспользуемой бизнес-логики
- ✅ Сложных ветвлений и проверок
- ✅ Композиции Skills в процесс
- ✅ Логики, которая часто меняется (версионирование!)

### Используй PromptGraph для:
- ✅ Промптов, которые используются в разных местах
- ✅ Промптов, которые часто меняются
- ✅ Промптов с переменными
- ✅ A/B тестирования промптов

### Используй Skills (Dart код) для:
- ✅ Атомарных операций (чтение файла, вызов API)
- ✅ Сложной логики (парсинг, вычисления)
- ✅ Интеграций с внешними системами
- ✅ Производительно-критичных операций

## 🚀 Рекомендации для разработки

### Для доработки движка

1. **WorkflowGraph:**
   - Реализовать условные рёбра (conditional)
   - Добавить timeout для узлов
   - Добавить retry механизм
   - Улучшить обработку ошибок

2. **InstructionGraph:**
   - Сделать maxSteps настраиваемым
   - Добавить узел loopAction (цикл с условием)
   - Добавить узел parallelAction
   - Реализовать Test Runner

3. **PromptGraph:**
   - Добавить условные блоки (if/else)
   - Добавить циклы (для списков)
   - Реализовать вложенные промпты
   - Добавить функции (length, uppercase, etc.)

### Для реализации воркеров

1. **Горизонтальное масштабирование:**
   - GraphWorker + Redis = N воркеров параллельно
   - Каждый воркер берёт задания из очереди
   - Результаты пишутся обратно в очередь

2. **Мониторинг:**
   - Метрики: количество запусков, средняя длительность, процент ошибок
   - Алерты при падении графов
   - Dashboard с визуализацией

3. **Отказоустойчивость:**
   - Retry при временных ошибках
   - Dead Letter Queue для проблемных заданий
   - Health checks для воркеров
