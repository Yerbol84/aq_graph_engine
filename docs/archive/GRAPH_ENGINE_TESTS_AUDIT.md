## ❌ КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. **ФЕЙКОВЫЙ ТЕСТ waitAll - САМАЯ БОЛЬШАЯ ПРОБЛЕМА**

```dart
test('Diamond pattern с waitAll: узел D выполняется один раз', () async {
  // ПРИМЕЧАНИЕ: Текущая реализация FileWriteNode использует firstCome,
  // поэтому узел D выполнится дважды.
  // Этот тест документирует текущее поведение.
  // TODO: Когда добавим поддержку waitAll в конкретные узлы, обновить тест.
```

**ЧТО ЗА ХРЕНЬ?!**

- Тест называется "узел D выполняется ОДИН раз"
- В комментарии написано "выполнится ДВАЖДЫ"
- Тест НЕ ПРОВЕРЯЕТ что узел выполнился один раз
- Тест НЕ ПРОВЕРЯЕТ что узел выполнился дважды
- Тест просто проверяет что файл существует

**Это не тест - это ЛОЖЬ в названии!**

**Что должно быть:**
```dart
// Либо переименовать:
test('Diamond pattern с firstCome: узел D выполняется дважды (текущее поведение)', () async {
  // И РЕАЛЬНО проверить что выполнился дважды через логи или счётчик
});

// Либо пропустить:
test('Diamond pattern с waitAll: узел D выполняется один раз', () async {
  // SKIP: waitAll не поддерживается в FileWriteNode
}, skip: 'waitAll not implemented in concrete nodes yet');
```

**Оценка:** 0/10 - это не тест, это обман

### 2. **НЕТ ПРОВЕРКИ КОЛИЧЕСТВА ВЫПОЛНЕНИЙ**

Все diamond pattern тесты проверяют только `File.exists()`. Это НЕ проверяет:
- Сколько раз узел выполнился
- В каком порядке узлы выполнились
- Правильно ли работает waitAll

**Что нужно:**
```dart
// Добавить счётчик выполнений в логи
final logs = await _repo.getRun(runId);
final logsJson = jsonDecode(logs['logsJson']);
final nodeDExecutions = logsJson.where((log) =>
  log.contains('Executing: fileWrite [nodeD]')).length;

expect(nodeDExecutions, 2, reason: 'Node D should execute twice with firstCome');
```

**Оценка:** 2/10 - проверка есть, но поверхностная

### 4. **НЕТ ПРОВЕРКИ ЛОГОВ waitAll**

Реализация добавляет логи:
```dart
_log('⏳ Node [${edge.targetId}] waiting for $remaining more edge(s)');
_log('✅ All ${incomingEdges.length} edges arrived at [${edge.targetId}]');
```

**НИ ОДИН ТЕСТ НЕ ПРОВЕРЯЕТ ЭТИ ЛОГИ!**

Как мы знаем что waitAll работает? Никак! Тесты не проверяют.

**Что нужно:**
```dart
test('waitAll: узел ждёт все входящие рёбра', () async {
  // ... setup ...

  final events = engine.run(request);
  await expectCompleted(events);

  final logs = await _repo.getRun(runId);
  final logsJson = jsonDecode(logs['logsJson']);

  // Проверить что был лог ожидания
  final hasWaitingLog = logsJson.any((log) =>
    log.contains('waiting for') && log.contains('more edge'));
  expect(hasWaitingLog, true, reason: 'Should log waiting for edges');

  // Проверить что был лог прибытия всех рёбер
  final hasAllArrivedLog = logsJson.any((log) =>
    log.contains('All') && log.contains('edges arrived'));
  expect(hasAllArrivedLog, true, reason: 'Should log all edges arrived');
});
```

**Оценка:** 0/10 - новая функциональность не протестирована

### 8. **СЛАБЫЕ ПРОВЕРКИ В СУЩЕСТВУЮЩИХ ТЕСТАХ**

#### Тест "Ветвление: onSuccess и onError пути"
```dart
expect(await File(successOutput).exists(), true);
expect(await File(errorOutput).exists(), false);
```

**Проблема:** Не проверяет ПОЧЕМУ errorOutput не существует. Может:
- onError ребро не выполнилось (правильно)
- onError ребро выполнилось, но упало с ошибкой
- onError ребро заблокировано exclusive

**Нужно:** Проверить логи что onError ребро было заблокировано exclusive.

**Оценка:** 3/10

---

#### Тест "Параллельное выполнение: несколько стартовых узлов"
```dart
expect(await File(output1).exists(), true);
expect(await File(output2).exists(), true);
expect(await File(output3).exists(), true);
```

**Проблема:** Не проверяет что узлы выполнились ПАРАЛЛЕЛЬНО. Может они выполнились последовательно.

**Нужно:** Проверить timestamp в логах или длительность выполнения.

**Оценка:** 4/10

---

#### Тест "Ошибка в середине цепочки останавливает выполнение"
```dart
expect(await File(output1).exists(), true, reason: 'Node1 should execute before error');
expect(await File(output2).exists(), false, reason: 'Node3 should not execute after error');
```

**Проблема:** Не проверяет что node2 УПАЛ С ОШИБКОЙ. Проверяет только что node3 не выполнился.

**Нужно:** Проверить логи что node2 упал с ошибкой и onSuccess ребро не выполнилось.

**Оценка:** 5/10
