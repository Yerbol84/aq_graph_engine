## ⚠️ ЧТО НЕ РАБОТАЕТ / ОГРАНИЧЕНИЯ

### 1. Join Strategies НЕ РЕАЛИЗОВАНЫ

**Проблема:**
- ❌ Нет `waitAll` - узел не ждёт все входящие рёбра
- ❌ Нет `firstCome` - узел выполняется при каждом ребре
- ❌ Нет `exclusive` - первое ребро не блокирует остальные

**Что это значит:**
```
Diamond pattern: A → B,C → D

Текущее поведение:
- Узел D выполнится ДВАЖДЫ (по разу на каждое ребро)

Ожидаемое поведение (с waitAll):
- Узел D должен выполниться ОДИН раз после прихода обоих рёбер
```

**Impact на production:**
- ⚠️ Diamond patterns работают некорректно
- ⚠️ Слияние параллельных веток не работает как ожидается
- ⚠️ Может привести к дублированию действий

**Workaround:**
- Избегать diamond patterns
- Использовать только последовательные и параллельные ветки без слияния

**Статус:** ❌ КРИТИЧНОЕ ОГРАНИЧЕНИЕ

### 2. Suspend/Resume НЕ ПОЛНОСТЬЮ РЕАЛИЗОВАНО

**Проблема:**
- ⚠️ Suspend работает (генерирует userInputRequired)
- ❌ Resume API может быть не полностью протестирован
- ❌ Нет гарантии восстановления контекста

**Impact на production:**
- ⚠️ Интерактивные workflows могут работать нестабильно
- ⚠️ Нет уверенности в восстановлении после паузы

**Workaround:**
- Использовать только автоматические workflows без пауз
- Тестировать suspend/resume перед использованием

**Статус:** ⚠️ ТРЕБУЕТ ТЕСТИРОВАНИЯ

### 3. Масштабирование НЕ ПРОТЕСТИРОВАНО

**Проблема:**
- ❌ Нет нагрузочных тестов
- ❌ Неизвестно поведение под нагрузкой
- ❌ Нет метрик производительности

**Impact на production:**
- ⚠️ Неизвестно сколько одновременных запусков выдержит
- ⚠️ Может быть bottleneck на БД
- ⚠️ Нет понимания пределов системы

**Workaround:**
- Начать с малой нагрузки (10-50 запусков/час)
- Мониторить производительность
- Постепенно увеличивать нагрузку

**Статус:** ⚠️ ТРЕБУЕТ НАГРУЗОЧНОГО ТЕСТИРОВАНИЯ

### 4. Мониторинг И АЛЕРТЫ НЕ НАСТРОЕНЫ

**Проблема:**
- ❌ Нет Prometheus метрик
- ❌ Нет Grafana дашбордов
- ❌ Нет алертов на ошибки
- ❌ Нет трейсинга (OpenTelemetry)

**Impact на production:**
- ⚠️ Сложно отследить проблемы
- ⚠️ Нет visibility в production
- ⚠️ Реактивный подход вместо проактивного

**Workaround:**
- Использовать логи
- Мониторить БД напрямую
- Настроить базовые алерты на уровне инфраструктуры

**Статус:** ❌ КРИТИЧНО ДЛЯ PRODUCTION

### 5. Отказоустойчивость НЕ ПРОТЕСТИРОВАНА

**Проблема:**
- ❌ Что происходит при падении Graph Engine во время выполнения?
- ❌ Что происходит при потере соединения с БД?
- ❌ Есть ли механизм retry?
- ❌ Есть ли graceful shutdown?

**Impact на production:**
- ⚠️ Риск потери данных
- ⚠️ Риск зависших workflows
- ⚠️ Нет гарантий восстановления

**Workaround:**
- Использовать для некритичных workflows
- Иметь план ручного восстановления
- Мониторить состояние сервиса

**Статус:** ❌ КРИТИЧНО ДЛЯ PRODUCTION

## 🚀 ROADMAP ДО ПОЛНОЙ PRODUCTION ГОТОВНОСТИ

### Фаза 1: Критичные доработки (1-2 недели)

**Приоритет: ВЫСОКИЙ**

1. **Реализовать Join Strategies**
   - waitAll - узел ждёт все рёбра
   - firstCome - узел выполняется при каждом ребре
   - exclusive - первое ребро блокирует остальные
   - **Impact:** Разблокирует diamond patterns
   - **Effort:** 3-5 дней

2. **Добавить мониторинг**
   - Prometheus метрики
   - Grafana дашборды
   - Базовые алерты
   - **Impact:** Visibility в production
   - **Effort:** 2-3 дня

3. **Протестировать отказоустойчивость**
   - Тесты на падение сервиса
   - Тесты на потерю соединения с БД
   - Graceful shutdown
   - **Impact:** Уверенность в надёжности
   - **Effort:** 2-3 дня

### Фаза 2: Важные улучшения (2-3 недели)

**Приоритет: СРЕДНИЙ**

4. **Нагрузочное тестирование**
   - 100 одновременных запусков
   - 1000 запусков в час
   - Найти bottlenecks
   - **Impact:** Понимание пределов
   - **Effort:** 3-5 дней

5. **Retry механизм**
   - Автоматический retry при ошибках
   - Exponential backoff
   - Конфигурируемое количество попыток
   - **Impact:** Повышение надёжности
   - **Effort:** 2-3 дня

6. **Улучшить Suspend/Resume**
   - Полное тестирование
   - Гарантии восстановления контекста
   - Timeout для suspended workflows
   - **Impact:** Интерактивные workflows
   - **Effort:** 3-5 дней

### Фаза 3: Дополнительные улучшения (3-4 недели)

**Приоритет: НИЗКИЙ**

7. **Трейсинг (OpenTelemetry)**

   - **Impact:** Глубокая observability

8. **Runbook и документация**
